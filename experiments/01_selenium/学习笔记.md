# 实验 01 学习笔记：用 Selenium 爬取动态网页

## 这个实验在做什么

用 Selenium 模拟真人操作浏览器，登录一个带筛选和分页的动态网站（模拟"集信达"短信服务日志后台），把表格里的日志数据逐条抓下来存成 JSON。对应课程里的"抓取动态网页数据"——那些内容是 JavaScript 运行后才出现的，普通的 `requests.get` 只能拿到一个空壳 HTML。

**5 分钟看懂**：你打开一个网站，看到的数据不是页面源码里就有的，而是浏览器跑完 JS 才"画"上去的。`requests` 只会拿源码，所以抓不到。Selenium 的作用是**真的启动一个浏览器**，让它把页面跑完，你再像人一样去"看"页面上已经渲染好的元素。这个实验里我们先自己用 Flask 搭了一个这样的动态网站（`app.py`），再用 Selenium（`my_spider.py`）去爬它——相当于自己出题自己答，方便调试。

## 前置知识与核心原理

### 为什么 requests 抓不到动态页面

浏览器拿到 HTML 后，还会执行里面的 `<script>`。这些脚本可能再去请求一个接口（比如 `/api/logs`），拿到数据后才把表格填进页面。`requests.get(url)` 只下载最初的 HTML，**不执行 JS**，所以你看到的 `response.text` 里表格是空的。这就是"静态爬取失败"的根本原因。

### Selenium 和 WebDriver 是什么

- **Selenium**：一个让程序控制浏览器的工具库。你写代码告诉它"点这个按钮、填这个输入框、等那个元素出现"，它就真的去操作浏览器。
- **WebDriver**（这里是 ChromeDriver）：Selenium 和 Chrome 之间的"翻译官"。Selenium 发指令，ChromeDriver 转成 Chrome 听得懂的话。所以你需要本机装 Chrome 浏览器和对应版本的 ChromeDriver。

### 显式等待在等什么

动态页面的数据不是瞬间就有的。如果你刚打开页面就去找表格元素，很可能还没渲染出来，代码就报错"找不到元素"。`WebDriverWait(driver, 15).until(...)` 的意思是：**最多等 15 秒，每隔一小会儿检查一次条件，条件满足就立刻继续**。本实验里等的是"表格里出现 8 列的数据行"（跳过"数据加载中"的占位行）。

### 本实验里这些概念怎么落地

| 概念 | 在本实验的体现 |
|---|---|
| 动态渲染 | `app.py` 的 `/api/logs` 接口返回数据，前端 JS 再填表格 |
| Selenium 操作 | 登录、点菜单、填筛选、点搜索、翻页 |
| 显式等待 | `wait_real_data()` 等真实数据行出现 |
| 无头模式 | `--headless=new`，不弹窗，后台跑完自动关 |

## 代码逐段拆解

### 1. 启动浏览器（无头模式）

```python
options = webdriver.ChromeOptions()
options.add_argument('--headless=new')
options.add_argument('--window-size=1400,900')
driver = webdriver.Chrome(options=options)
```

`--headless=new` 让 Chrome 在后台运行，不弹窗口，适合服务器/脚本场景。如果去掉这两行，你会看到一个浏览器窗口自动操作，调试时建议先去掉，跑通了再加回来。

### 2. 登录

```python
user = wait.until(EC.presence_of_element_located((By.ID, 'username')))
user.clear(); user.send_keys('admin')
pwd = driver.find_element(By.ID, 'password')
pwd.clear(); pwd.send_keys('123456')
driver.find_element(By.ID, 'login-btn').click()
```

注意 `user.clear()` 先清空再输入——如果不清空，第二次跑可能变成 `adminadmin`。`By.ID` 是按 `id` 属性找元素，本实验的页面元素都有明确的 id，所以用 ID 最稳。

### 3. 筛选 + 翻页循环

```python
while True:
    wait_real_data(wait)
    rows = parse_current_page(driver)
    all_data.extend(rows)
    next_btn = driver.find_element(By.ID, 'next-btn')
    if 'disabled' in (next_btn.get_attribute('class') or ''):
        break
    next_btn.click()
    time.sleep(1)
```

翻页的关键是**判断"下一页"按钮是否可点**。这里通过检查按钮的 class 里有没有 `disabled` 来判断是不是最后一页。`time.sleep(1)` 给页面一点时间加载下一页数据。

### 4. 解析当前页

```python
for row in driver.find_elements(By.CSS_SELECTOR, '#log-table tbody tr'):
    tds = row.find_elements(By.TAG_NAME, 'td')
    if len(tds) != 8:
        continue
```

`#log-table tbody tr` 是 CSS 选择器，意思是"id 为 log-table 的元素里面，tbody 下面的所有 tr（行）"。每行有 8 个 td（单元格），对应序号、时间、通道、签名、模板、应用、耗时、状态。这里特意跳过不是 8 列的行，因为可能有"数据加载中"的占位行。

### 常见报错排查

- **`SessionNotCreatedException`**：ChromeDriver 版本和 Chrome 浏览器版本不匹配，下载对应版本的 ChromeDriver。
- **`NoSuchElementException`**：元素还没加载出来就去找了，检查是不是漏了 `WebDriverWait`，或者选择器写错了。
- **抓不到数据**：先确认 `app.py` 已经启动且端口是 5000。

## 踩坑与经验小结

1. **输入框要先 `clear()` 再 `send_keys()`**，否则重复运行会叠加。
2. **动态页面一定要等**，用 `WebDriverWait` 比 `time.sleep` 更高效（满足条件立刻走，不傻等）。
3. **无头模式适合跑通后再开**，调试时先看浏览器实际在做什么。
4. **翻页终止条件要可靠**，本实验用"下一页按钮 class 含 disabled"判断，比数页数更稳。
5. **数据行可能有占位行**，解析时按列数过滤一下。
