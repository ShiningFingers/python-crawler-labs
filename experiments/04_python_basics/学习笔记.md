# 实验 04 学习笔记：学生成绩管理系统（tkinter）

## 这个实验在做什么

用 Python 内置的 `tkinter` 库做一个带图形界面的学生成绩管理系统，支持增、删、改、查、排序、CSV 导入导出。对应课程里的"Python 程序设计基础"——练习面向对象、列表操作、GUI 事件驱动。

**5 分钟看懂**：tkinter 是 Python 自带的 GUI 库，不用装第三方包。你创建一个窗口，往里放输入框、按钮、表格，再给每个按钮绑一个函数，点按钮就执行对应的逻辑。本实验的数据都存在一个内存列表 `self.students` 里，表格只是这个列表的"投影"，改列表再刷新表格就行。

## 前置知识与核心原理

### tkinter 的基本套路

```python
import tkinter as tk
window = tk.Tk()              # 创建主窗口
tk.Label(window, text='xxx').pack()   # 放一个标签
window.mainloop()            # 进入事件循环，等用户操作
```

- **窗口（Tk）**：最外层容器。
- **控件（Widget）**：Label（文字）、Entry（输入框）、Button（按钮）、Treeview（表格）等。
- **布局**：`pack()`（上下堆叠）、`grid()`（网格）、`place()`（坐标）。本实验主要用 `pack`。
- **事件驱动**：给按钮绑 `command=函数名`，点按钮就调函数。

### 为什么用列表做"唯一数据源"

界面上的表格只是展示，真正的数据存在 `self.students` 列表里。每次增删改后调用 `refresh_table()` 把列表重新画到表格上。好处是：数据和展示分离，不会出现"表格里改了但数据没变"的不一致。

### 学号作为主键

表格的行号（Treeview 的 iid）刷新后会变，但学号不变。所以用学号来定位"当前编辑的是哪条记录"，而不是记行号。这是 `current_sid` 变量的作用。

## 代码逐段拆解

### 1. 全局配置

```python
COURSES = ['语文', '数学', '英语']
SID_LENGTH = 8
SCORE_MIN = 0
SCORE_MAX = 100
```

把"科目列表、学号长度、成绩范围"放在最上面，改配置就改这里。比如想加一门"物理"，只需要往 `COURSES` 里加 `'物理'`，后面的下标都会自动推算（`TOTAL_IDX = SCORE_START + len(COURSES)`）。

### 2. 校验函数（纯逻辑，不碰界面）

```python
def validate_score(text):
    try:
        value = float(text)
    except (TypeError, ValueError):
        return False, '成绩必须是数字！'
    if not math.isfinite(value):
        return False, '成绩必须是有效数字（不能是 nan / inf）！'
    if value < SCORE_MIN or value > SCORE_MAX:
        return False, f'成绩必须在 {SCORE_MIN}~{SCORE_MAX} 之间！'
    return True, value
```

这一层是"工具函数"，不依赖界面，可以单独测试。注意 `math.isfinite(value)`——`float('nan')` 不会触发 ValueError，也能通过范围判断，必须单独拦掉。

### 3. 数据访问层

```python
def find_index_by_sid(students, sid):
    for i, stu in enumerate(students):
        if stu[IDX_SID] == sid:
            return i
    return -1
```

纯函数操作列表，和界面无关。`find_index_by_sid` 按学号找下标，`is_sid_exists` 判断学号是否重复（修改时排除自己）。

### 4. 主类初始化

```python
class StudentSystem:
    def __init__(self):
        self.window = tk.Tk()
        self.students = []
        self.current_sid = None
        self.build_ui()
        self.refresh_table()
```

`self.students` 是内存数据源，`self.current_sid` 记录当前编辑的学号。初始化时搭界面 + 刷新表格。

### 5. 界面搭建

```python
def build_ui(self):
    self._build_title()
    self._build_input_area()
    self._build_button_area()
    self._build_query_area()
    self._build_sort_area()
    self._build_table_area()
    self._build_status_bar()
```

把界面拆成多个子函数，每个负责一块区域。这样代码清晰，写报告时也方便按区域讲解。


### 预期效果

弹出一个 900×660 的窗口，有标题、数据录入区、按钮区、查询区、排序区、表格、状态栏。可以录入学号（8 位数字）、姓名、三科成绩，点"添加"后表格出现一行，自动算总分和平均分。

### 常见报错排查

- **`ModuleNotFoundError: No module named 'tkinter'`**：Linux 上可能没装 tkinter，Ubuntu 执行 `sudo apt install python3-tk`。Windows/Mac 自带。
- **学号报"必须是 8 位数字"**：检查输入的学号是不是 8 位纯数字。
- **表格不刷新**：检查改完 `self.students` 后有没有调 `refresh_table()`。

## 踩坑与经验小结

1. **数据和展示分离**：列表是唯一数据源，表格只是投影，改完数据记得 `refresh_table()`。
2. **用学号做主键，别用行号**：表格刷新后行号会变，学号不会。
3. **校验函数要独立于界面**：方便测试，也让主类不臃肿。
4. **配置放最上面**：科目、范围等常量集中管理，改一处全局生效。
5. **`float('nan')` 是个坑**：必须用 `math.isfinite()` 单独拦截。
