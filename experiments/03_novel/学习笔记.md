# 实验 03 学习笔记：爬取网络小说（剑来 + 极品家丁）

## 这个实验在做什么

用 `requests` + `PyQuery` 爬取网络小说的多个章节并保存到本地 txt 文件。实验分三组递进：①爬《剑来》单章和十章（复现课堂模板）；②换站点爬《极品家丁》时发现"请求成功却抓不到数据"，定位为 JS 动态渲染；③分析《极品家丁》章节 URL 的数字递增规律，直接构造 URL 批量爬取。对应课程里的"静态网页爬取标准流程"。

**5 分钟看懂**：小说网站的每一章就是一个网页，标题和正文都在 HTML 里。爬虫要做的就是：拿到目录页 → 解析出所有章节链接 → 逐个打开章节页 → 提取标题和正文 → 写进 txt。本实验的亮点是碰到了"有些网站内容靠 JS 生成，requests 抓不到"的问题，并学会了另一种思路——不解析目录，直接靠 URL 规律拼出所有章节地址。

## 前置知识与核心原理

### 静态网页爬取五步

1. 设定目标（哪个网站、哪些章节）
2. 分析目标网站（章节链接在 HTML 的哪个位置）
3. 批量下载 HTML（requests.get）
4. 解析 HTML 提取数据（PyQuery + CSS 选择器）
5. 存储到本地文件

### 编码处理：为什么会乱码

服务器返回的 HTML 是字节流，requests 需要知道用什么编码解码成文字。`response.encoding` 是从 HTTP 响应头猜的，如果响应头没写 charset，requests 默认用 `ISO-8859-1`，中文就会乱码。`response.apparent_encoding` 是从内容本身分析出来的编码，通常更准。所以标准做法是：

```python
response.encoding = response.apparent_encoding
```

### CSS 选择器在小说站的典型用法

| 选择器 | 作用 |
|---|---|
| `#list > dl > dd > a` | 目录页里所有章节链接 |
| `.bookname > h1` | 章节标题 |
| `#content` | 章节正文 |

`>` 表示"直接子元素"，避免选到嵌套深处的同名标签。

### 为什么 requests 抓不到动态页面

《极品家丁》的站点（bqg616.cc）目录页内容是 JS 渲染的。`requests` 拿到的 HTML 里没有章节列表，所以 `doc('#list > dd > a')` 抓到 0 条。判断方法：看 `len(resp.text)`，如果很短说明拿到的是空壳；看 `resp.url`，如果 `#` 后面的部分被丢了，说明这个 URL 本身就是前端路由，服务器不返回内容。

### URL 规律爬取

如果章节 URL 是 `域名/目录/数字.html`，且数字连续递增，就不需要解析目录页，直接 `for i in range(10): url = base + str(start + i) + '.html'` 拼出来。这比解析目录更简单，也避开了 JS 渲染问题。

## 代码逐段拆解

### 单章爬取（剑来单章爬取.py）

```python
url = "https://www.biquwx.la/1_1245/603316.html"
response = requests.get(url)
response.encoding = response.apparent_encoding

doc = pq(response.text)
title = doc('.bookname > h1').text()
content = doc('#content').text()

with open('剑来.txt', mode='w+', encoding='utf-8') as f:
    f.write(title); f.write('\n'); f.write(content); f.write('\n')
```

这是最小可用版本：请求 → 处理编码 → 取标题正文 → 存文件。`mode='w+'` 覆盖写入，第一次创建文件用。

### 十章爬取（剑来十章爬取.py）

```python
response = requests.get(CATALOG_URL, headers=headers)
doc = pq(response.text)
links = doc('#list > dl > dd > a')

count = 0
for link in links.items():
    if count >= MAX_CHAPTERS:
        break
    chapter_url = CATALOG_URL + link.attr.href
    ...
    with open(OUTPUT_FILE, mode='a+', encoding='utf-8') as f:
        f.write(title); f.write('\n'); f.write(content); f.write('\n')
    time.sleep(DELAY)
```

关键点：
- 先请求**目录页**，用 `#list > dl > dd > a` 拿到所有章节链接。
- `CATALOG_URL + link.attr.href` 把相对路径拼成完整 URL。
- `count >= MAX_CHAPTERS`（10）控制只爬前 10 章。
- 第一章用 `w+` 创建文件，后续用 `a+` 追加写入。
- `time.sleep(2)` 每章间隔 2 秒。

### 极品家丁 JS 动态渲染分析（实验二爬取极品家丁js.py）

```python
resp = requests.get(CATALOG_URL, headers=headers)
print('页面HTML长度：', len(resp.text))   # 太短可能就是没拿到内容
doc = pq(resp.text)
links = doc('#list > dd > a')
print('抓到章节数：', len(links))         # 0 说明是动态渲染
```

这段代码的目的是**定位问题**：打印 HTML 长度和抓到的章节数。如果长度很短且章节数为 0，就证明这个站点是 JS 动态渲染，requests 拿不到目录。

### URL 规律爬取极品家丁（爬取前十章极品家丁用数字规律.py）

```python
base_url = 'http://www.xbiquwk.com/10_10243/'
start_num = 5023899

for i in range(10):
    num = start_num + i
    url = base_url + str(num) + '.html'
    resp = requests.get(url, headers=headers)
    ...
    mode = 'w+' if i == 0 else 'a+'
```

发现章节 URL 最后是连续数字后，直接循环 `start_num + i` 拼 URL，省去了解析目录的步骤。`mode = 'w+' if i == 0 else 'a+'` 用三元表达式决定写入模式。

## 实验历程

基于 5 个 .py 文件和报告，演进路径清晰：

1. **单章验证**：先写 `剑来单章爬取.py`，确认请求→编码→解析→存文件的流程跑通，能拿到"第一卷 笼中雀 第一章 惊蛰"。
2. **十章目录爬取**：扩展为 `剑来十章爬取.py`，加目录页解析、10 章上限、2 秒间隔、追加写入。
3. **换站点踩坑**：换成 bqg616.cc 爬《极品家丁》，用 `实验二爬取极品家丁js.py` 诊断出"HTML 太短 + 章节数为 0"，确认是 JS 动态渲染导致 requests 失效。
4. **URL 规律优化**：改到 xbiquwk.com，发现章节 URL 是连续数字，用 `爬取前十章极品家丁用数字规律.py` 直接构造 URL 批量爬取，绕开目录解析。
5. **极品家丁单章验证**：`极品家丁爬取单章.py` 确认新站点的选择器（`.bookname > h1` 和 `#content`）同样适用。

### 常见报错排查

- **中文乱码**：`response.encoding = response.apparent_encoding` 这行必须加。
- **抓到章节数为 0**：站点是 JS 动态渲染，换一个静态站点或用 URL 规律。
- **403 Forbidden**：加 `User-Agent` 请求头（本实验已加）。
- **爬取中断**：单章失败用 `try/except` 跳过，别让一章失败拖垮整个爬取。

## 踩坑与经验小结

1. **`response.encoding = response.apparent_encoding` 是中文爬虫的标配**，不加必乱码。
2. **先打印 HTML 长度和抓到的数量**，快速判断是静态还是动态页面。
3. **目录解析和 URL 规律是两种互补策略**：目录解析通用但依赖页面结构；URL 规律简单但需要站点 URL 有规律。
4. **首章 `w+`、后续 `a+`**，这是多文件追加写入的标准模式。
5. **`time.sleep(2)` 是基本操作**，爬太快容易被封 IP。
